Laravel x Shopify

Connecting Laravel to Shopify with Webhooks and a Thank You Page Extension

By Sonali Dudhia • May 28, 2026 • 10 min read

Laravel Shopify Webhooks Checkout UI

In one project, I worked on a Shopify integration where the store needed to trigger custom post-purchase logic inside a Laravel application. The app was connected to the Shopify store, listened to webhook events, updated order-related data, and exposed a custom flow from the Thank you page back into Laravel.

The project started as a private app setup. Today, you would usually describe this kind of build as a custom app, but the core architecture stays the same: Shopify owns the commerce flow, and Laravel handles the business logic that sits around it.

What the Integration Needed to Do

The requirements were straightforward, but the flow had a few moving parts:

  • Connect the app to a Shopify store securely.
  • Receive webhook events whenever order activity changed.
  • Update Laravel-side records and trigger internal workflows.
  • Allow post-purchase data collection after successful payment.
  • Send the customer from the Thank you page into a Laravel-managed form.

Instead of trying to overload checkout itself, I kept the payment flow clean and handled the extra business process after the order was already created.

High-Level Architecture

Shopify Store
    |
    |-- Webhooks (orders/create, orders/updated, etc.)
    v
Laravel Webhook Endpoint
    |
    |-- Validate HMAC
    |-- Persist webhook payload
    |-- Dispatch queued job
    v
Laravel Business Logic
    |
    |-- Update local records
    |-- Call Shopify Admin API if needed
    v
Thank you Page Extension
    |
    |-- Customer clicks custom link
    v
Laravel Form
    |
    |-- Save response
    |-- Continue internal workflow

Receiving Shopify Webhooks in Laravel

Webhooks were the backbone of the integration. Whenever an order changed, Shopify notified the Laravel app. The first thing I cared about here was verifying the request properly before touching the payload.

A simple route looked like this:

use App\Http\Controllers\ShopifyWebhookController;
use Illuminate\Support\Facades\Route;

Route::post('/webhooks/shopify/orders', ShopifyWebhookController::class);

The controller used the raw request body and the X-Shopify-Hmac-Sha256 header to verify that the webhook was genuinely sent by Shopify:

First, verify the signature:

$rawBody = $request->getContent();
$receivedHmac = $request->header('X-Shopify-Hmac-Sha256', '');

$computedHmac = base64_encode(
    hash_hmac('sha256', $rawBody, config('services.shopify.webhook_secret'), true)
);

if (! hash_equals($computedHmac, $receivedHmac)) {
    abort(401, 'Invalid signature.');
}

Then dispatch the payload into a queue:

ProcessShopifyOrderWebhook::dispatch(
    $request->header('X-Shopify-Topic'),
    $request->header('X-Shopify-Shop-Domain'),
    $request->json()->all()
);

return response()->json(['ok' => true]);

The main goal was to acknowledge fast and move real work into a queue. That kept the webhook endpoint responsive and safer under retries.

Processing the Webhook Asynchronously

Once the payload was trusted, I handed it to a job. This is where I mapped Shopify data into the Laravel domain and triggered the project-specific logic.

The job constructor keeps the webhook context small and explicit:

public function __construct(
    public string $topic,
    public string $shopDomain,
    public array $payload
) {}

Inside handle(), I sync the order into Laravel:

$order = ShopifyOrder::updateOrCreate(
    ['shopify_order_id' => $this->payload['id']],
    [
        'shop_domain' => $this->shopDomain,
        'order_number' => $this->payload['order_number'] ?? null,
        'email' => $this->payload['email'] ?? null,
        'financial_status' => $this->payload['financial_status'] ?? null,
        'payload' => $this->payload,
    ]
);

After that, I can trigger Shopify-side updates only when needed:

if ($this->topic === 'orders/create') {
    $shopify->tagOrder(
        $this->shopDomain,
        $order->shopify_graphql_id,
        ['post-purchase-pending']
    );
}

In the real project, the exact logic depended on the order state and what the Laravel app needed to do next. The important part was that Shopify events became triggers for application workflows, instead of data that someone had to check manually.

Updating the Shopify Order from Laravel

Sometimes receiving the webhook was only half the job. After processing the event, the Laravel app also needed to update something back in Shopify, such as order tags, notes, or a custom status marker.

I usually keep that logic behind a small service so controllers and jobs stay readable:

A small GraphQL mutation is enough for tagging:

$query = <<<GRAPHQL
mutation AddTags($id: ID!, $tags: [String!]!) {
  tagsAdd(id: $id, tags: $tags) {
    node {
      id
    }
    userErrors {
      field
      message
    }
  }
}
GRAPHQL;

Then the service can send the request with the store token:

return Http::withHeaders([
    'X-Shopify-Access-Token' => $this->tokenFor($shopDomain),
])->post("https://{$shopDomain}/admin/api/2025-10/graphql.json", [
    'query' => $query,
    'variables' => [
        'id' => $orderGid,
        'tags' => $tags,
    ],
])->json();

If the project requires true order editing rather than simple metadata updates, the same pattern applies: receive the webhook, decide the business action in Laravel, then call the appropriate Shopify Admin API mutation from a service class.

Adding a Thank You Page Extension

The second half of the project was the customer-facing part. After a successful payment, I needed to show a custom link on the Thank you page that would send the customer into a Laravel form.

That extension acted as the bridge between Shopify checkout completion and the Laravel workflow.

First, register the Thank you page extension target:

import {
  reactExtension,
  BlockStack,
  Link,
  Text,
} from "@shopify/ui-extensions-react/checkout";

export default reactExtension(
  "purchase.thank-you.block.render",
  () => <Extension />
);

Then build the Laravel redirect URL from the order context:

const orderId = "gid://shopify/Order/1234567890";
const shop = "example-store.myshopify.com";

const formUrl =
  `https://app.example.com/shopify/post-purchase?shop=${encodeURIComponent(shop)}&order=${encodeURIComponent(orderId)}`;

Finally, render the call to action on the page:

return (
  <BlockStack spacing="tight">
    <Text emphasis="bold">One more step</Text>
    <Link to={formUrl}>Complete the follow-up form</Link>
  </BlockStack>
);

The UI itself was small, but it unlocked a much larger workflow. It let me collect data after payment, without disrupting the checkout process.

Handling the Laravel Form Submission

Once the customer clicked the link, Laravel took over. I used a normal route and controller to show the form and then store the response. 

use App\Http\Controllers\PostPurchaseFormController;

Route::get('/shopify/post-purchase', [PostPurchaseFormController::class, 'show']);
Route::post('/shopify/post-purchase', [PostPurchaseFormController::class, 'store']);

The GET action only needs to forward the order context into the view:

return view('shopify.post-purchase', [
    'shop' => $request->string('shop'),
    'order' => $request->string('order'),
]);

The POST action validates and stores the response:

$data = $request->validate([
    'shop' => ['required', 'string'],
    'order' => ['required', 'string'],
    'response' => ['required', 'string', 'max:5000'],
]);

PostPurchaseResponse::create($data);

return redirect()->route('thank-you.local');

In this setup, the Laravel app became the source of truth for the extra information the business needed after checkout.

Things That Mattered in Production

  • Verify webhook signatures using the raw body, not parsed JSON.
  • Process webhooks asynchronously to avoid timeouts and duplicate side effects.
  • Store the Shopify order ID and shop domain consistently across tables.
  • Protect the external form flow so only valid post-purchase requests are accepted.
  • Keep Shopify-specific API calls behind a service layer.

Why This Pattern Worked Well

What I liked about this architecture is that each system stayed focused on what it does best. Shopify handled checkout and order creation. Laravel handled custom workflows, validation, persistence, and follow-up processing.

That separation made the solution easier to maintain and gave the project room to grow. Adding more webhook topics, more internal workflow steps, or more post-purchase screens on the Laravel side was straightforward once the integration foundation was in place.

Final Thoughts

If you need more than the default Shopify admin flow, Laravel works very well as the backend layer around a Shopify store. Webhooks give you reliable event triggers, the Admin API lets you push changes back into Shopify, and a Thank you page extension gives you a clean post-purchase entry point into your own application.

For this project, that combination made it possible to connect store events, customer actions, and Laravel business logic into one consistent flow.
